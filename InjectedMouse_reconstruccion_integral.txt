5. WEBVIEW2
======================================================================

Se identifican dos superficies WebView:

MainWebView
PipWebView

La aplicación carga:

https://www.xbox.com/play/
https://www.xbox.com/play
https://www.xbox.com/play/search

También aparecen referencias a:

gamepass.com
xbox.com

El uso de WebView2 encaja con el mecanismo documentado por Microsoft:

window.chrome.webview.postMessage(...)
        ->
CoreWebView2.WebMessageReceived

Microsoft documenta que WebMessageReceived se dispara cuando el documento de nivel superior ejecuta window.chrome.webview.postMessage y la mensajería está habilitada. La página puede enviar objetos JSON al host y el host puede recibirlos como JSON/string. Fuente:
https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2

La documentación actual de Microsoft también describe ExecuteScriptAsync, NavigationStarting, NavigationCompleted, WebMessageReceived y PostWebMessageAsJson/PostWebMessageAsString para este patrón de integración. Fuente:
https://learn.microsoft.com/es-es/windows/apps/develop/ui/controls/webview2

La documentación indica además que WebMessageReceived recibe los mensajes del documento y que los mensajes de un mismo frame mantienen su orden relativo, aunque no hay garantía de orden entre frames o frente a determinadas APIs DOM. Fuente:
https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2

23. WINDOWS INPUT INJECTION
======================================================================

El nombre:

InputInjectionRemapper

es consistente con las APIs de Windows para inyección programática de entrada.

Windows dispone de APIs de Windows.UI.Input.Preview.Injection y relacionadas con generación de input. Microsoft documenta, por ejemplo, InputInjector.InjectGamepadInput para inyectar gamepad input en escenarios permitidos.

También WebView2 dispone de mecanismos nativos de entrada; CoreWebView2CompositionController incluye métodos para enviar mouse/pointer input.

Documentación:
https://learn.microsoft.com/en-us/uwp/api/windows.ui.input.preview.injection.inputinjector.injectgamepadinput?view=winrt-26100
https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2compositioncontroller

La arquitectura más probable es una combinación de:
- APIs de Windows
- APIs de WebView2
- JavaScript DOM

No debe asumirse que una sola API sea responsable de toda la entrada.
